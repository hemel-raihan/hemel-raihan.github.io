01

Overview

The MVP explores a remittance experience similar in product scope to Wise or Taptap Send. It uses a pre-funded payout model rather than a SWIFT transfer: liquidity is positioned in advance so the destination-side payout can be processed locally after the source-side transaction is confirmed.

Laravel transaction backendSpring Boot FX microserviceFlutter mobile appLedger-based accountingSandbox callbacks
Transfer model

Source-side collection → transaction-period FX lock → ledger-backed settlement → payout from pre-funded destination liquidity. The MVP does not model a direct SWIFT wire.

02

Product goal

The objective was to validate the technical shape of an end-to-end pre-funded remittance product: clear FX pricing, recipient management, dependable transaction state, traceable fund movement, destination liquidity and integration boundaries for future banking partners.

03

My role

I designed and implemented the Laravel transaction backend, ledger structure and core remittance processes. I also built and integrated a Java Spring Boot microservice for FX conversion and rate locking, and connected those services to the Flutter prototype.

AI-assisted prototyping

I used Claude as an AI-assisted coding tool to accelerate parts of the Flutter interface prototype. I defined the product flows, backend contracts, transaction architecture and service integration, while using AI to shorten the UI exploration cycle.

04

What I designed and implemented

  • Recipient creation and management for simulated cross-border transfers.
  • Pre-funded settlement and local payout flow rather than direct SWIFT transfer processing.
  • FX quote, currency conversion and transaction-period rate locking through a Spring Boot microservice.
  • Laravel-based transaction orchestration and status processing.
  • Ledger structure for traceable debit, credit and simulated fund movement.
  • Flutter user journeys for recipient selection, quote review and transfer progression.
  • Test callback functions that simulate asynchronous bank confirmation in a sandbox flow.
05

Key engineering challenges

Rate consistency

Keeping the quoted FX rate stable during the permitted transaction window.

Liquidity state

Representing source collection and destination pre-funded payout without treating the flow as a SWIFT wire.

Ledger integrity

Representing fund movement as balanced, traceable entries rather than simple status updates.

Asynchronous confirmation

Testing transaction progression when banking confirmation arrives later through a callback.

06

Architecture and solution

The prototype separates customer experience, transaction orchestration and FX logic so each part can evolve independently and future banking integrations can attach to clear boundaries.

From sandbox to production

The present MVP uses test callbacks instead of live banking infrastructure. A production release would require regulatory approval and country-specific banking partnerships before processing real transfers.

08

Outcome

The functional MVP validates an end-to-end remittance flow and demonstrates a modular approach to transaction processing, FX rate management, ledger-backed movement and future bank integration—without presenting the prototype as a released financial product.
